This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Language Rules

- Code comments: English
- Commit messages, PR titles, PR bodies: English
- Variable and function names: English

## Git Conventions

GitMoji + Conventional Commits with a scope: `<emoji>(<scope>): <summary>`

Emojis: ✨ feature, 🐛 bugfix, ♻️ refactor, ✅ test, 📝 docs, 🎨 structure, ⚡️ perf, 🔥 remove, 🔧 configuration,
⬆️ dependency update, 🔒️ security, 🚧 WIP

Scopes used so far: `cornix-lp` (keymap and firmware behaviour), `ci`, `deps`, `mise`, `renovate`

- Commit messages should describe the **purpose/intent** of the change, not what was changed
- PRs are squash-merged: the title becomes the commit subject and the body becomes the commit body
- PR title: follow the `<emoji>(<scope>): <summary>` format
- PR body: explain the purpose and context of the change
- Do NOT add Co-Authored-By or any other trailers
- Do NOT add "Generated with Claude Code" footers or session URLs to commits or PR bodies
- `main` is protected by rulesets: every change goes through a PR, and `CodeQL (rust)` must pass

### Branch Naming

Conventional Branch format: `<type>/<description>` (lowercase, hyphens only)

Types: `feature/`, `fix/`, `hotfix/`, `release/`, `chore/`

## Build & Test Commands

The build tools are pinned in `.config/mise/config.toml` and locked in `.config/mise/mise.lock`; run
`mise install` once per clone. The Rust toolchain comes from `rust-toolchain.toml`.

```bash
mise run lint    # cargo fmt --check + clippy (firmware on the MCU target, cornix-led on the host)
mise run test    # unit tests of cornix-led on the host
mise run build   # both halves -> firmware/rmk-cornix-{central,peripheral}.uf2
```

The firmware binaries are `no_std` for `thumbv7em-none-eabihf` (the default target in `.cargo/config.toml`),
so their test targets do not build. Only `led/` is unit-tested, and it runs on the host target.

`./flash.sh left|right` copies a UF2 image onto the half in bootloader mode (macOS).

## Architecture

RMK firmware for the Cornix LP split keyboard (nRF52840, BLE split, Vial).

- `keyboard.toml` — RMK's keyboard definition: matrix, split, BLE, encoders, event subscriber limits and
  the keymap. The block between `# >>> generated by gen-rmk-keymap.py` and `# <<< generated` is generated
  from a Pipette snapshot outside this repository; edit the snapshot, not the block
- `vial.json` — the Vial definition; `build.rs` compresses it into the firmware
- `src/central.rs`, `src/peripheral.rs` — the two binaries (`#[rmk_central]`, `#[rmk_peripheral]`)
- `src/ws2812.rs`, `src/deadline.rs` — the WS2812 status LED driver and the deadline-driven processor loop
- `led/` (`cornix-led`) — status LED logic: facts in, colours and the next wake-up out. Dependency-free
  and hardware-free so it builds and tests on the host
- `Cargo.toml` `[patch.crates-io]` — `rmk` comes from the ryotan/rmk fork (branch `ryotan/main`);
  `Cargo.lock` pins the commit

RMK derives `BUILD_HASH` from the build time and reruns its build script only when it changes, so
`mise run build` cleans `rmk` first. A new hash makes RMK erase its storage and Bluetooth bonds on flashing.

## Coding Philosophy

- **FP-first**: Prefer pure functions, immutable data, and iterator chains. Use structs/enums for data,
  functions for behavior. Isolate side effects at boundaries: hardware stays in `src/`, logic in `led/`.
- **TDD**: Red-Green-Refactor cycle for the host-testable logic. Tests serve as specifications.
- **Implementation order**: Type design → Pure functions → Side-effect separation → Adapter implementation
- **Start small**: Avoid excessive abstraction. Focus on types rather than code. Extend incrementally.
